URLを返すツールの作り方

指定された「画像アップロード 3.app」を実際に読み取り、同じ仕組みをゼロから作る手順にしました。GitHub登録、リポジトリ準備、スクリプト、アプリ化、テスト、配布まで説明します。

まず結論：このツールがしていること

画像を特別なサービスへ直接送るのではなく、GitHubのリポジトリへ保存し、そのファイルのURLを表示・コピーしています。

ファイルをドロップ→AppleScript→Shell→GitHubへpush→URL
重要：現在の実物は WellConsultant/claude-seminar-lp へ送る設定です。Publicリポジトリなら画像も公開されます。顧客資料や秘密の画像は送らないでください。

作るもの

  • 1個をドロップしてURLを返す
  • 複数個をドロップして一覧URLを返す
  • アップロード履歴を保存する

必要なもの

  • Mac
  • GitHubアカウント
  • GitHub DesktopまたはGit
  • スクリプトエディタ

全体像を理解する

アプリは受付係、Shellは作業係、GitHubは倉庫です。

部品役割実物の場所
AppleScriptアプリドロップされたファイルを受け取りShellを呼びます。画像アップロード 3.app
1個用Shell拡張子・サイズ確認、コピー、commit、push、URL表示。~/claude-seminar-lp/tools/upload-image.sh
複数用Shell複数ファイルと一覧ファイルをまとめてpush。~/claude-seminar-lp/tools/upload-batch.sh
GitHub作業コピーファイルを置くローカルのGitリポジトリ。~/.claude/tools/claude-seminar-lp-uploads

1. GitHubを登録する

GitHub公式の登録ページを開き、メールアドレス、パスワード、ユーザー名を登録します。確認メールを開き、できれば2段階認証またはパスキーも設定します。

アカウントを作る

仕事用なら管理できるメールアドレスを使います。ユーザー名はURLの一部になります。

リポジトリを作る

ログイン後、右上の「＋」→「New repository」を選びます。

設定する

Repository nameは my-image-uploads など。迷ったらPrivate。READMEは最初は作らなくて構いません。

公式：アカウント作成 / リポジトリ作成

2. MacとGitHubをつなぐ

このツールは裏側でGitのpushを行うため、MacからGitHubへ送れる状態が必要です。

初心者にはGitHub Desktopがおすすめです。インストールして「Sign in to GitHub.com」を押し、ブラウザで許可します。

ターミナルを使う場合は、次を実行します。

git --version
git config --global user.name "あなたの名前"
git config --global user.email "GitHubに登録したメールアドレス"

GitHubへの接続はHTTPSまたはSSHです。SSHでは秘密鍵を他人に渡さず、公開鍵だけをGitHubへ登録します。

公式：Gitのセットアップ / SSH接続

3. アップロード用フォルダとShellを作る

ターミナルで次を1ブロックずつ実行します。

mkdir -p "$HOME/claude-seminar-lp/tools"
mkdir -p "$HOME/.claude/tools/claude-seminar-lp-uploads/uploads"

GitHubリポジトリの「Code」からURLをコピーして、次を実行します。URLは自分のものに置き換えてください。

git clone https://github.com/あなたのユーザー名/my-image-uploads.git "$HOME/.claude/tools/claude-seminar-lp-uploads"
mkdir -p "$HOME/.claude/tools/claude-seminar-lp-uploads/uploads"

1個用Shell

~/claude-seminar-lp/tools/upload-image.shを作り、次の内容を貼り付けます。

#!/bin/bash
set -e
REPO_DIR="$HOME/.claude/tools/claude-seminar-lp-uploads"
SRC="$1"
MAX_BYTES=99614720
EXT=$(basename "$SRC" | sed 's/.*\.//' | tr '[:upper:]' '[:lower:]')
case "$EXT" in
  jpg|jpeg|png|gif|webp|svg|pdf|mp4|mov|m4v|html|htm) ;;
  *) echo "対応していない拡張子です" >&2; exit 1 ;;
esac
SIZE=$(stat -f%z "$SRC")
[ "$SIZE" -le "$MAX_BYTES" ] || { echo "大きすぎます" >&2; exit 1; }
NAME="$(openssl rand -hex 3).$EXT"
mkdir -p "$REPO_DIR/uploads"
cp "$SRC" "$REPO_DIR/uploads/$NAME"
cd "$REPO_DIR"
git fetch origin main --quiet
git reset --hard FETCH_HEAD --quiet
git add "uploads/$NAME"
git commit -m "Add uploaded file" --quiet
git push origin main --quiet
echo "https://raw.githubusercontent.com/あなたのユーザー名/my-image-uploads/main/uploads/$NAME"
chmod +x "$HOME/claude-seminar-lp/tools/upload-image.sh"
実物にはpush失敗時の戻し処理、HTMLをhtmlpreviewで開く処理、履歴追記も入っています。実運用ではそれらを残してください。

4. 複数ファイル用を追加する

upload-batch.shは複数ファイルを uploads/b-ランダム名/ に置き、元の名前とURLを書いた index.txt を返します。

#!/bin/bash
set -e
REPO_DIR="$HOME/.claude/tools/claude-seminar-lp-uploads"
RAW_BASE="https://raw.githubusercontent.com/あなたのユーザー名/my-image-uploads/main"
BATCH="uploads/b-$(openssl rand -hex 3)"
mkdir -p "$REPO_DIR/$BATCH"
MANIFEST="$REPO_DIR/$BATCH/index.txt"
: > "$MANIFEST"
for SRC in "$@"; do
  [ -f "$SRC" ] || continue
  EXT=$(basename "$SRC" | sed 's/.*\.//')
  NAME="$(openssl rand -hex 3).$EXT"
  cp "$SRC" "$REPO_DIR/$BATCH/$NAME"
  echo "$(basename "$SRC") -> $RAW_BASE/$BATCH/$NAME" >> "$MANIFEST"
done
cd "$REPO_DIR"
git add "$BATCH"
git commit -m "Add batch upload" --quiet
git push origin main --quiet
echo "$RAW_BASE/$BATCH/index.txt"

5. AppleScriptをアプリにする

Macの「スクリプトエディタ」をSpotlightで開きます。次を貼り付け、ファイル形式を「アプリケーション」にして保存します。

on run
  display dialog "画像をこのアプリにドロップしてください。" buttons {"閉じる"}
end run

on open theFiles
  if (count of theFiles) > 1 then
    set batchScript to (POSIX path of (path to home folder)) & "claude-seminar-lp/tools/upload-batch.sh"
    set fileArgs to ""
    repeat with aFile in theFiles
      set fileArgs to fileArgs & " " & quoted form of (POSIX path of aFile)
    end repeat
    set theURL to do shell script quoted form of batchScript & fileArgs
  else
    set uploadScript to (POSIX path of (path to home folder)) & "claude-seminar-lp/tools/upload-image.sh"
    set theURL to do shell script quoted form of uploadScript & " " & quoted form of (POSIX path of (item 1 of theFiles))
  end if
  set the clipboard to theURL
  display dialog theURL with title "アップロード完了（リンクはコピー済み）" buttons {"開く","閉じる"} default button "開く"
  if button returned of result is "開く" then open location theURL
end open

保存

「ファイル」→「書き出す」→ファイル形式「アプリケーション」。新しい名前で保存します。

テスト

画像を1個ドロップし、URLが表示されるか確認します。

配布

アプリだけを渡しても動きません。受け取るMacにもShell、Git、認証、リポジトリが必要です。

6. 完成後の使い方

1個の場合

  1. 画像をアプリへドロップ。
  2. push完了まで待つ。
  3. 表示されたURLを使う。
  4. URLは自動でコピー済み。

複数の場合

  1. 画像を複数選択。
  2. まとめてドロップ。
  3. 返った index.txt を開く。
  4. 一覧からURLを使う。

履歴は ~/アップロード履歴.txt に残ります。GitHub上の uploads/ も確認してください。

症状確認・対処
リポジトリがない~/.claude/tools/claude-seminar-lp-uploads/.gitがあるか。正しいURLでcloneします。
pushで止まるGitHub Desktopでログインするか、HTTPS/SSH認証を設定します。
拡張子エラーjpg、png、gif、webp、svg、pdf、mp4、mov、m4v、html、htmだけが対象です。
大きすぎる実物は99,614,720 bytes（約95MiB）を超えると止まります。
URLが開けないGitHub上にファイルがあるか、URLのユーザー名・リポジトリ名を確認します。
アプリが無反応AppleScriptをスクリプトエディタで開き、エラーを確認します。

8. 安全対策

Publicリポジトリは秘密の保管庫ではありません。顧客情報、契約書、未公開資料、個人写真は送らないでください。

迷ったらPrivate

社内用ならPrivateを選びます。ただしPrivateのraw URLを外部ページへ埋め込めるとは限りません。

公開用と保管用を分ける

Webページで公開する素材だけを公開用リポジトリに置きます。

秘密情報を書かない

パスワード、トークン、秘密鍵をShellやAppleScriptへ直書きしません。

誤送信時は削除だけで終わらせない

GitHubの履歴に残る場合があります。漏れた鍵は無効化し、必要なら履歴対策を行います。
