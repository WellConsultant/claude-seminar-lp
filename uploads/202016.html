申請を始める前に
終わらせる手続きと加点準備

デジタル化・AI導入補助金2026について、申請前に必要な手続き、加点の選び方、準備書類、不備を避ける確認事項を一つにまとめたガイドです。

対象地域全国
申請区分新規
申請方法電子申請のみ
申請手数料0円

最初に確認すること

交付申請の前に、少なくとも「GビズIDプライム」と「SECURITY ACTION」の準備が必要です。加点を受ける場合は、申請枠と締切から逆算し、該当する手続きを申請前に完了させます。

必須 1

GビズIDプライムを取得する。エントリー、メンバーでは申請できません。資料191：通常枠公募要領 p.7／資料268

必須 2

SECURITY ACTIONの「一つ星」または「二つ星」を自己宣言する。申請時に自己宣言IDを照合します。資料200：通常枠公募要領 p.48

加点

申請する枠に対応する加点だけを選び、必要な登録・面談・PDF出力・証明書類を締切前にそろえます。資料99：加点項目一覧 2026/6/3版

交付決定前に契約・発注・支払いをしない 一部でも先に行うと補助対象外となり、不備訂正では解消できません。資料225：交付申請マニュアル p.8

確認項目判断基準確認方法・注意点根拠
法人日本国内で法人登記され、法人番号が指定・公表されている。日本国内に本社と補助事業の実施場所がある。法人番号、登記、本社・実施場所を確認する。資料102：電子取引類型FAQ No.1
個人事業主日本国内に補助事業の実施場所がある。本人確認書類、確定申告書類、実施場所を確認する。資料102：電子取引類型FAQ No.1
事業実態製品・サービスの生産・提供など、生産活動に資する事業を行っている。申請内容、決算・申告書類と事業実態の整合を確認する。資料144：電子取引類型公募要領 p.9
IT導入支援事業者との関係2026年事業のIT導入支援事業者（構成員を含む）として登録済み・登録予定の事業者、およびその代表者・役員が経営する企業ではない。役員・関係会社を含めて確認する。資料146：電子取引類型公募要領 p.10／資料112：FAQ No.13

  • 宗教法人
  • PTA、同窓会などの任意団体

申請前の必須手続き

1．GビズIDプライム

必要なアカウント

通常必要依頼者が取得

申請に使えるのはGビズIDプライムです。GビズIDエントリー、GビズIDメンバーでは申請できません。資料191 p.7／資料268

確認できる状態

取得済みというだけでなく、申請者自身がID・パスワードを管理し、ポータルサイトへログインできる状態にします。申請マイページの開設にも使います。資料273：申請前手続きWEBページ

2．SECURITY ACTION

原則

通常必要依頼者が宣言

「★ 一つ星」または「★★ 二つ星」を自己宣言し、交付申請作成時に自己宣言IDを入力します。セキュリティ対策推進枠は二つ星が前提です。資料191 p.7／資料99

第2次公募以降

資料では、新システムで申し込んだ自己宣言IDのみ利用可能とされています。旧システムIDでは申請提出できません。資料8：照合ニュース

GビズIDの一致を確認 SECURITY ACTIONの申込みに用いるGビズIDと、補助金申請マイページへのログインに用いるGビズIDプライムは、完全に同一である必要があります。資料9：照合ニュース

くるみん・えるぼし

認定者のみ

交付申請時点で、えるぼし（1〜3段階目・プラチナ）または、くるみん・トライくるみん・プラチナくるみんの認定を受けていることが必要です。資料99／資料194 p.22

該当者のみ

交付申請締切日時点で会員登録し、挑戦課題を「掲載中」として登録していることが条件です。資料99／資料194 p.22

省力化ナビ

該当者のみ

交付申請締切日時点で「省力化ナビ」を活用し、「解決策」のPDFをダウンロードしていることが必要です。GビズIDプライムの入力が必要です。資料161：通常枠公募要領改訂履歴 p.2

認定者のみ

健康経営優良法人2026の認定が加点項目とされています。認定区分・確認方法の詳細は申請時点の資料で要確認です。資料99

通常枠で追加検討する加点

デジタル化セカンドオピニオン

通常枠・第3回公募以降事前予約・面談

登録確認者（中小企業診断士等）とのオンライン面談を申請締切までに完了します。予約時は最低3日以上の日程候補を入力します。面談時の具体的な合否判定基準など、資料で確定できない運用は要確認です。資料99／資料119：申請者向けマニュアル p.3／資料196 p.24

インボイス対応類型で追加検討する加点

インボイス登録の約束

交付申請時点では未登録で、実績報告日までに登録し、登録通知書を提出することを約束する場合の加点です。資料99／資料172 p.25

スマートレジの選定

第3回公募以降。カテゴリ1（ソフトウェア）とカテゴリ9（POSレジ等）の双方が「スマートレジ」として登録されていることが条件です。資料99／資料161 p.2

準備書類

交付申請時の代替書類は認められないとされています。資料名、発行日、税目、年度、個人情報の有無を提出前に確認します。資料180：通常枠公募要領 p.11

期限・申請方法・費用

申請方法

事務局が提供する申請マイページから電子申請します。紙の郵送、窓口持込みは受け付けていません。資料224 p.8

予約

通常の交付申請に予約は不要です。セカンドオピニオン加点を使う場合は、オンライン面談の事前予約が必要です。資料119 p.3

申請手数料

0円。GビズIDプライムの利用料も資料上は発生しません。将来にわたる無料を約束するものではありません。資料214 p.11

推奨環境

Windows環境のMicrosoft Edge、Google Chromeの各最新版。資料213 p.11

止まりやすい点・不備防止

個人情報が残っている

マイナンバー、保険者番号等が見える添付ファイルは事務局で削除されます。判別できない状態に黒塗りしてから提出します。資料194 p.23

納税証明書ではなく領収書

必要なのは税務署発行の納税証明書「その1」または「その2」です。法人税・所得税の別、直近分かを確認します。資料194 p.23

SECURITY ACTIONのID不一致

自己宣言IDの誤りや、申請用GビズIDとの不一致は不採択につながるとされています。新旧システムの別も確認します。資料230 p.42

交付決定前に契約等をした

契約・発注・支払いを交付決定前に行うと補助対象外です。申請前だけでなく、交付決定まで社内で発注を止めます。資料225 p.8

加点手続きが締切後

「交付申請前」「交付申請時点」「締切日時点」「申請締切までに面談完了」など基準時が異なります。登録しただけで完了と思わないようにします。

課題とツールが合っていない

期待する導入効果が、自社の状況・課題分析・将来計画と一致しているかを確認します。資料195 p.24

資料差・要確認事項

賃上げ計画の年平均成長率は、申請枠ごとに切り替えて確認 通常枠・セキュリティ対策推進枠の資料には「給与支給総額の年平均成長率1.5％以上」とある一方、インボイス枠の資料には「1人当たり給与支給総額3.5％以上」、過去の交付決定状況によって「3％以上」とする記載があります。共通基準として一つの数値を使わず、申請する枠の最新公募要領で確認してください。
資料41 p.18／資料81 p.22／資料147 p.11／資料150 p.23／資料179 p.8
SECURITY ACTIONの「一つ星」と「二つ星」 一般の申請要件は一つ星または二つ星です。セキュリティ対策推進枠では二つ星が前提です。申請枠を確定したうえで宣言区分を選びます。資料191 p.7／資料99

資料だけでは確定できない事項

  • デジタル化セカンドオピニオン面談の具体的な判定基準と、公開資料にない詳細運用
  • 第5次以降の締切、最終受付終了時期
  • 令和7年分の確定申告書を用意できない場合に認められる具体的事情、理由書、代替証憑
  • 第1次公募で申請し、不備訂正が第2次以降にずれ込んだ場合の旧SECURITY ACTION IDの扱い
  • 各認定・登録加点について、申請画面で必要となる具体的な添付形式または照合方法

事務局へ確認する質問

  1. 第1次公募で旧システムの自己宣言IDを使い、不備訂正が第2次公募以降になった場合、新システムでの再取得が必要か。
  2. 個人事業主が令和7年分の確定申告書を用意できない場合、認められる事情と必要な補足資料は何か。
  3. 申請予定の枠・公募回における賃上げ加点の基準値、基準時、必要な表明・添付方法は何か。
  4. 申請予定の加点について、登録・認定状況はシステム照合か、証明書添付か。

申請前の最終チェック

  • 申請する枠・類型と公募回を確定した
  • 申請者が対象者要件を満たし、対象外要件に該当しないことを確認した
  • GビズIDプライムでログインできる
  • SECURITY ACTIONを新システムで宣言し、自己宣言IDを確認した
  • SECURITY ACTIONと申請マイページのGビズIDが完全に一致する
  • 使う加点を申請枠別に選び、各基準時までに手続きを終えた
  • IT戦略ナビwithを使う場合、正しいGビズIDが表示されたIT戦略マップPDFを用意した
  • 賃金状況報告シートは2026年用の該当様式を使った
  • 法人・個人の区分に応じた必要書類をすべて用意した
  • 証明書の発行日、有効期限、年度、税目を確認した
  • マイナンバー、保険者番号等を判別できないように黒塗りした
  • 申請情報、登記・申告書類、事業実態、導入目的に矛盾がない
  • 交付決定前の契約・発注・支払いがない
  • IT導入支援事業者との共同入力後、申請者自身が全内容を確認した
  • 申請者本人がSMS認証できる携帯電話を準備した
